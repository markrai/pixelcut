## 3A.7a import classification

Keep the existing strict HLG renderer and original FromReport constructor. FromImportReport is the explicit broader media-bin admission boundary. It uses Stream.ClassifySourceColor before creating an asset. Source bytes remain unchanged. HLG assets retain their old serialized representation and import behavior. Classified SDR/PQ assets may be saved, relinked, deduplicated and removed, but **cannot be placed on any timeline track** in this slice. Project validation also rejects a hand-authored clip using a classified bin-only asset. Unused bin assets do not affect HLG export. No conversion or source relabeling takes place.

Supported initial descriptors:

- Existing square-pixel 10-bit 4:2:0 BT.2020 HLG contract unchanged.
- H.264/HEVC planar yuv420p or yuv420p10le SDR with BT.709 primaries, matrix and transfer, tv/pc range, left/center chroma and square pixels.
- Explicit HEVC yuv420p10le BT.2020 nonconstant-luminance PQ (smpte2084) with explicit range, chroma and square pixels. Classification only; no PQ render claim.

For 8-bit planar H.264/HEVC whose longer coded side is at least 1280 and shorter side at least 720, missing/unknown/unspecified tags may be interpreted as BT.709 primaries/transfer/matrix, limited range, left chroma and square pixels. A missing SAR of 0:1 is also treated as unspecified. This is a provisional HD SDR convention, not proof of the source's intended colors. Never override a conflicting explicit tag, infer HDR, infer missing 10-bit color, or infer missing SD color. Fully tagged smaller SDR is accepted. Inference is reported in the media-bin label and persisted as flags (primaries 1, transfer 2, matrix 4, range 8, chroma 16, SAR 32); before rendering is enabled, provide a documented override/confirmation policy. No guesses about the user's specific screen recording without inspecting it. Reject unsupported codec/pixel format, odd dimensions, conflicting metadata, non-square geometry, unsupported display matrix/side data, multiple ordinary video or audio streams and unknown auxiliary streams for classified sources. Existing HLG restrictions remain intact.

Schema 11 adds optional color_family, color_defaults, codec, pixel_format, chroma fields on classified assets; existing range records effective range, and family fixes the effective primaries/transfer/matrix. Descriptor is comparable by value so clipboard, relink and dedup remain deterministic. Earlier versions 1-10 remain readable without migration on load; v10 transitions still valid. Importing a classified asset upgrades the project. New projects and latest-version feature edits use v11; older releases reject v11. Cached metadata namespace is revised to retain only rotation and the recognized Pixel metadata handler tags required for safety; old stripped reports cannot bypass rotation checks.

## 3A.7c whole-project HLG output with SDR sources

The timeline export gate from 3A.7b is superseded for confirmed/tagged SDR BT.709. Whole-project HLG export (including SDR-only projects) re-probes every contributing source, verifies the exact classified descriptor including assumptions, and retains source identity checks through publication. Audio-only SDR contributions are admitted without video conversion. PQ and unconfirmed SDR remain bin-only. Unused assets are not probed. Selected SDR clip export and native SDR output remain gated; schema 12 is unchanged.

Fixed initial color policy (not a display-referred mastering guarantee): normalize source range and chroma to limited-range BT.709 10-bit 4:4:4 with explicit zscale input/output tags; apply existing geometry. Recover nonlinear BT.709 RGB, clamp to nominal range, invert the BT.709 camera transfer (linear below 0.081, power 1/0.45 otherwise), multiply linear RGB by the BT.709-to-BT.2020 primary matrix, and scale by inverse HLG(0.75), approximately 0.264963. Neutral SDR white becomes HLG signal 0.75 (limited 10-bit Y=721), not HDR peak white. Black stays Y=64. This scene-referred convention is deliberately fixed for reproducibility; SDR display gamma/creative looks and alternative reference white settings are not inferred. Geometry uses the existing encoded-domain scaling; the SDR layer is quantized once into HLG 10-bit 4:4:4 before entering the existing scene-linear opacity/dissolve compositor. No SDR preview pixels enter export. Existing HLG normalization and compositing remain unchanged.

SDR is decoded on CPU by design, even with CUDA preference; eligible HLG retains requested CUDA decode, no retry/fallback after hardware failure. Encoding uses existing CPU x265 or explicit NVENC, unchanged output verification and audio mux. In-place conversion is bounded by the existing per-layer geometry cap, occurs once per selected decoded source frame (not each repeated CFR sample), and observes cancellation between rows. Full-resolution performance and physical color appearance remain unqualified. GUI export confirmation describes the mapping; source labels no longer say preview-only.

Do not claim perceptual equality to native SDR or the SDR preview.

## 3A.7d whole-project BT.709 SDR output

Explicit `-color sdr` (or the SDR export menu) selects H.264 High / avc1, limited-range 8-bit BT.709 4:2:0, left chroma, square pixels. HLG remains available. The existing geometry and source normalization yield 10-bit 4:4:4 working layers. SDR layers remain native BT.709; HLG layers are converted once per selected source frame before the shared scene-linear compositor. SDR opacity and dissolve invert the BT.709 camera curve and encode with the corresponding OETF. Opaque native SDR layers are copied without an HLG round trip. Final encoding reduces to 8-bit. Audio, timing, cancellation, bounded resources, identity and no-overwrite publication contracts are shared.

Fixed scene-referred HLG tone policy: decode HLG to BT.2020 linear RGB, compute BT.2020 luminance L, and map L linearly to 0.75 at inverse HLG(0.75). Above that knee a rational shoulder is continuous in value and first derivative and maps L=1 to 1. Scale RGB by the luminance ratio, convert linear primaries to BT.709, and compress out-of-gamut colors toward equal-channel luminance while preserving luminance within numerical precision. Encode BT.709 and quantize to 10-bit working layers. SDR reference white remains full nominal SDR white; the mapped HLG reference white is intentionally lower to reserve highlight headroom. This is not a display-referred BT.2390 mastering implementation or a guarantee of preview/export visual parity.

CPU libx264 and explicit experimental h264_nvenc share the same pre-encode buffers and verified output contract. Eligible HLG sources may use CUDA decoding; SDR sources use CPU by design. No automatic hardware failure fallback. PQ and selected SDR clip export remain gated. Schema unchanged.
